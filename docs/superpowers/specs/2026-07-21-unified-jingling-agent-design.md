# 统一鲸灵 Agent（单仓 / 多仓）— 设计文档

## 术语（对内开发必用）

| 说法 | 含义 | 代码宿主 |
|------|------|----------|
| **单仓鲸灵** | 主窗内嵌；绑定当前打开的 Git 项目；**只能**访问该项目上下文 | `host: "project"` |
| **多仓鲸灵** | 独立子窗；可访问应用内**已登记**多仓（首期只读画像 + 插件） | `host: "global"` |

二者对外对内产品名都叫 **鲸灵**，是**同一套 Agent**；唯一硬差异是上下文范围与首期能力开关。  
旧名「鲸履 / 简历帮」废弃；简历是**插件之一**，不是独立产品。

## 背景

原先主窗「鲸灵」与子窗「鲸履」为两套 prompt / Store / Service。现合并为一套 Agent 壳 + 插件，按宿主分桶会话。

## 决策摘要

| 项 | 选择 |
|----|------|
| 产品名 | 只叫鲸灵（单仓 / 多仓为对内分工说法） |
| 架构 | 统一壳 + `AgentHost`；能力渐进 |
| 会话 | 宿主分桶，互不混用 |
| 单仓 | 当前仓 Git 快照 / 分支 @；可挂插件；禁止跨仓 |
| 多仓 | 多仓只读画像 + 插件（简历等）；**暂不**跨仓写 Git / 全量 Git 工具 |
| 设置 | 原「鲸履」入口并入「鲸灵」；提供「打开多仓鲸灵」 |
| 侧栏 | 「新增会话」→「插件」按钮→插件列表；无「插件/会话」分区标题 |
| 插件市场 | 非目标 |

## 非目标（本轮）

- 多仓鲸灵跨仓执行写 Git / 完整 Git Agent 工具面
- 插件安装市场、第三方沙箱
- 单仓会话与多仓会话互通
- 一次 PR 内完成所有 `jinglv*` 符号物理删除（允许分阶段迁名，但产品文案本轮清掉「鲸履」）

---

## §1 产品与入口

### 单仓鲸灵

- 位置：仓库主界面 Agent 面板
- 打开即绑定 `projectId` + `repoPath`
- 会话：`project_id` 必填；删项目 CASCADE

### 多仓鲸灵

- 位置：设置 → 鲸灵 →「打开多仓鲸灵」；状态栏等入口同步改文案
- 子窗标题：鲸灵（或多仓鲸灵，UI 克制用「鲸灵」+ 副文案说明多仓）
- 会话：`project_id` 为空；仅手动删除
- 路由 / window label：可暂留 `jinglv` 兼容，对外不可见；目标改为 `agent-global`（实现计划分阶段）

### 设置 → 鲸灵

- API Key、余额、Git 助手指令、**简历指令**、联系信息（原鲸履身份）
- 「打开多仓鲸灵」按钮
- 删除独立「鲸履」设置分类

## §2 代码模型

```ts
/** 鲸灵宿主：决定上下文边界与能力开关 */
export type AgentHost = "project" | "global";
```

目标形态：

```
UI AgentShell(host)
  → plugins/agent（简历等）
  → streamAgentReply({ host, projectId?, repoPath?, profiles?, … })
  → prompts 按 host / 启用插件组装
  → chat persist 按 host 分桶
```

| 层级 | 单仓 `project` | 多仓 `global` |
|------|----------------|---------------|
| Git 快照 | ✅ 当前仓 | ❌ 首期不做全量 Git Agent |
| 输入框 `@` | ❌ 单仓不启用（无分支 @） | ✅ 插件 / 项目 |
| 多仓只读画像 | ❌ | ✅ |
| 插件壳 | ✅ | ✅ |
| 简历插件 | ✅（仅当前仓） | ✅（可点名多仓） |
| 写 Git | 仅经现有确认流 | ❌ |

### 持久化

| 现网 | 目标 |
|------|------|
| `scope=agent` + `project_id` | 单仓鲸灵（可保留 scope 名 `agent`） |
| `scope=jinglv` | 多仓鲸灵；兼容读，目标 scope `agent_global`（或文档记为 global 桶） |

身份 Store：`jinglv.json` 可读兼容，目标并入 `ai` 相关 Store 或改名 `agent-identity.json`（计划内迁移）。

### 插件

- 注册表归属 `src/plugins/agent/`（由 `plugins/jinglv` 迁入）
- 侧栏：「插件」进入列表；点选插入 `@`；简历为首个

## §3 渐进迁移策略

1. **文档与术语** — 本文件 + `docs/product/ai.md` + `AGENTS.md`  
2. **产品改名与设置并入** — 用户可见「鲸履」清零  
3. **`AgentHost` + 插件目录** — 壳对齐，服务可暂双入口薄封装  
4. **统一 `streamAgentReply(host)`** — 合并 prompt 组装  
5. **scope / 路径物理清 jinglv** — 兼容期过后删除旧名  

每阶段保持可运行；禁止带着 S0/S1 交付。

## 成功标准

- 对内沟通「单仓鲸灵 / 多仓鲸灵」与文档一致  
- 用户界面无「鲸履」产品名  
- 设置仅「鲸灵」分类可打开多仓子窗并编辑联系信息  
- 单仓不可访问其它项目上下文；多仓首期无跨仓写 Git  
- `tsc` 通过
