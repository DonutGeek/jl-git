# 最近项目远程仓库标识设计

## 目标

在 Dashboard 的最近项目列表中，按需读取项目的主远程地址，并将当前展示的完整 URL 改为「代码托管平台图标 + 仓库名.git」。让用户无需阅读长 URL 即可识别仓库托管平台及其仓库名。

## 范围

- 支持 GitHub、GitLab、Gitee、Bitbucket。
- 同时识别 HTTPS URL 与常见 SSH（`git@host:owner/repo.git`）格式。
- 优先使用 `origin` 的 fetch URL；没有 `origin` 时使用第一个远端，保持现有选择逻辑。
- 未识别的域名显示通用 Git 图标；没有远端或读取失败时不显示远程仓库标识。
- 不修改项目持久化、Tauri Command 或 Git Service 的远端读取契约。

## 交互与展示

- 鼠标悬停或键盘聚焦一行最近项目时，异步读取远端，并在项目名称行右侧展示标识。
- 标识由 14–16px 托管平台图标和仓库最后路径段组成；仓库名保留原始 `.git` 后缀。
- 标识的 `title` 保留完整远程地址，双击标识时在系统浏览器打开完整地址；事件不触发项目打开。
- 图标为展示内容，`aria-hidden`；远程标识维持可键盘聚焦与现有双击行为。

## 图标策略

- 以本地 SVG 资源内置四个平台的品牌图标，避免新增 `react-icons` 或运行时网络请求。
- 通用 Git 图标使用项目已依赖的 `lucide-react`。
- 图标颜色使用当前文字色，不引入品牌色或硬编码主题色，保证 Light / Dark 主题一致。

## 数据流与边界

`RecentProjectList` → `gitService.listRemotes` → `pickPrimaryRemoteUrl` → 纯前端解析函数 → 展示数据。

解析函数仅处理字符串，不执行网络请求或 Git 操作。它应返回平台类型、仓库显示名和原始 URL，以便组件不再包含 URL 格式判断。

## 错误处理

读取远端失败时记录现有开发期 warning，并缓存空结果，避免每次悬停重复请求。未知地址不是错误，使用通用 Git 图标与解析到的末段仓库名。

## 测试与验收

- 为 URL 解析函数补充单元测试：四个平台的 HTTPS/SSH、未知平台、无 `.git` 后缀及无法解析的地址。
- 运行 TypeScript 检查。
- 桌面端冒烟：最近列表在 Light/Dark 下悬停、键盘聚焦、双击标识、无远端项目均正常；项目双击打开行为不受影响。

## 非目标

- 不支持通过用户配置自定义托管平台。
- 不在项目数据库中缓存远端地址。
- 不改变远端选择策略或 Git 凭据处理。
