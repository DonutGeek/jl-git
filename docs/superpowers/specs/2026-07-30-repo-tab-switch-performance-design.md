# 仓库标签即时切换体验

> 日期：2026-07-30  
> 状态：已实施

## 背景

当前标签激活通过 `requestAnimationFrame → setTimeout(0) → startTransition` 延迟路由。该组合只改变任务排队顺序，不保证浏览器已完成可见绘制；随后路由更新和 Zustand 仓库会话恢复仍可能在首帧前占用主线程。

正常切换时项目元数据通常已存在，`RepoPage` 不进入加载态，因此新标签高亮、页面切壳和仓库数据恢复容易被用户感知为一次整体卡顿。

## 目标

1. 点击仓库标签后，下一次可见绘制必须同时展示新标签高亮和新仓库页面壳。
2. 缓存恢复和 Git Store 切换都不得发生在目标页面壳完成首帧绘制之前。
3. 已有内存缓存的仓库优先恢复缓存内容，并在后台静默刷新状态。
4. 首次打开、无缓存的仓库在侧栏、中间工作区和右侧预览区分别显示局部 Loading。
5. 快速连续点击时，过期切换不得覆盖当前标签、当前仓库数据或错误状态。
6. 保持单个 `RepoPage` 和单个 `useRepoStore`，不为每个标签常驻完整仓库页面。

## 非目标

- 不引入多仓库 Zustand Store。
- 不同时挂载多个完整 `RepoPage`。
- 不修改标签分组、拖拽、关闭或持久化语义。
- 不预加载尚未访问仓库的 Git 数据。

## 方案

### 1. 激活状态与路由

- 删除标签激活路径中的 `requestAnimationFrame`、`setTimeout(0)` 和 `startTransition`。
- 点击时同步写入当前激活意图，使 `RepoTabBar` 和 `WorkspaceHost` 使用同一个目标标签。
- 同步请求 React Router 导航；URL 继续作为可恢复、可深链的稳定状态。
- 路由落地后清除临时激活意图。
- 点击当前标签保持无操作；连续点击以最后一次为准。

临时激活意图只用于覆盖路由提交前的极短窗口，不负责保存业务数据。

### 2. 立即切换轻量页面壳

`WorkspaceHost` 根据激活意图优先解析目标仓库，使标签高亮和内容目标在同一次 React 提交中一致。

`RepoPage` 收到不同 `projectId` 时：

- 立即切换项目名称、路径等轻量元数据。
- 若 `useRepoStore.repoPath` 尚未指向目标仓库，不渲染绑定旧 Store 的业务面板。
- 渲染轻量切换壳，避免出现“标签是 B、内容仍是 A”。
- 首帧不在 `useLayoutEffect` 或 render 阶段恢复缓存、清空 Store 或同步本地 State。
- 浏览器完成目标壳首帧后，再恢复缓存或切换 Repo Store。

### 3. 缓存优先与局部 Loading

目标仓库按缓存状态分流：

- **缓存命中**：首帧先展示目标仓库真实框架和极短局部 Loading；浏览器完成绘制后恢复内存会话，再后台执行轻量状态刷新。
- **缓存未命中**：立即展示目标仓库名称、真实工具栏、活动栏和分栏结构；变更视图在左侧栏内容、未暂存区、暂存区和右侧预览区居中显示 `Spinner + Loading`，中间底部直接展示禁用状态的真实提交区；工作区保留路径栏，只在路径栏下方的文件内容区显示 Loading；调用 `loadAll()` 后替换局部内容。
- **加载失败**：保留目标仓库身份和可重试错误态，不回退显示旧仓库内容。

Loading 复用现有 shadcn `Spinner` 和 i18n `common.loading` 文案，不使用 `Skeleton`。四个变更加载区域复用现有 `ResizableSplit`、`min-h-0`、`overflow-hidden` 布局约束；工具栏、活动栏、状态栏、路径栏和分隔线保持真实结构，不使用全屏阻塞 Loading。

局部加载态必须完整位于 `AppLayout` 的 `main` 区域内，不能覆盖或挤压底部 `StatusBar`，也不能与任一面板滚动条重合。

仓库标签条不显示会覆盖下层仓库工具栏的横向滚动条；触控板保留原生横向滚动，普通鼠标在标签区使用纵向滚轮时转换为横向滚动，激活标签仍自动滚入视口。标签内容末端保留 6px 安全间距，避免最后一个分组对齐视口右侧时圆角边框被裁切。

### 4. 竞态隔离

完整加载和 `refreshStatus()` 分别按仓库维护递增请求令牌；切仓时使离开仓库的旧状态刷新失效。异步阶段提交前检查：

- 当前激活仓库仍与请求目标一致。
- effect 尚未清理。
- Git 返回结果只能进入对应仓库缓存；非当前仓库不得写入当前 UI Store。

快速执行 `A → B → C` 时，只允许 C 更新当前页面。A、B 已完成的数据可以安全写回各自缓存，但不能改变高亮、页面目标或当前错误状态。

## 状态流程

```text
点击标签 B
  → 同步激活 B
  → 标签 B + B 的真实页面框架 + 精确局部 Loading 完成首帧
  → 检查 B 会话缓存
      ├─ 命中：恢复缓存 → 替换局部 Loading → 后台刷新 status
      └─ 未命中：切换 Repo Store → loadAll(B) → 替换局部 Loading
```

## 测试与验收

### 自动测试

1. 点击非当前标签后，激活意图立即变为目标标签。
2. 路由未落地时，标签栏与工作区解析为同一目标。
3. 路由落地后，临时激活意图被清除。
4. 缓存命中走恢复与轻量刷新，不触发完整首载。
5. 缓存未命中按真实内容边界显示局部 Loading 并执行完整加载。
6. 连续切换时，过期请求不能提交当前页面状态。

### 运行时验收

1. 在两个已有缓存的仓库之间连续切换，点击后首帧高亮与页面目标一致。
2. 首次打开仓库时立即出现对应仓库真实框架和精确局部 Loading，不显示前一个仓库内容。
3. 快速连续点击三个标签，最终内容始终对应最后一个标签。
4. Git 加载较慢或失败时，标签栏仍可继续响应和切换。
5. 新标签页与仓库页互切时不闪现旧仓库内容。
6. 局部 Loading 不覆盖底部状态栏，不与侧栏或主面板滚动条重合。

### 质量门槛

- `pnpm check` 通过。
- 相关运行时冒烟通过。
- 无新增 S0/S1；不以任意延时数值作为正确性条件。
