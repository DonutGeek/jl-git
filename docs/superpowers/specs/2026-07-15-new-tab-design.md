# 新标签页设计

> 日期：2026-07-15  
> 范围：仓库标签栏中的新标签页与仓库标签统一管理

## 目标

点击标签栏“+”后创建并激活一个标题为“新标签页”的标签。该标签展示现有初始页的仓库选择与最近仓库内容；没有已打开仓库时，应用默认展示它。

新标签页与仓库标签具有一致的交互：可切换、关闭、拖拽排序，并随现有标签状态恢复。

## 标签模型与持久化

`useOpenTabsStore` 从仅保存仓库 ID 的列表改为保存有序标签项。标签项分为：

| 类型 | 必要数据 | 标题 | 内容 |
| --- | --- | --- | --- |
| `repository` | `projectId` | 项目名称 | 现有仓库工作区 |
| `new-tab` | 稳定的标签 ID | 新标签页 | 初始仓库选择页 |

持久化保留两种标签及其排序。恢复后的新标签页继续显示仓库选择页，不访问 Git 数据。为兼容已有本地持久化数据，需要把旧的仓库 ID 数组迁移成 `repository` 标签项。

## 交互与路由

1. 点击“+”创建一个 `new-tab` 标签，激活它并导航到新标签页路由。
2. 新标签页沿用仓库标签的关闭、右键关闭操作和拖拽排序能力；仓库专属操作（移除项目、设置别名、复制路径与远端）不在新标签页提供。
3. 用户从新标签页打开或选择一个仓库时，当前 `new-tab` 原地替换为该仓库的 `repository` 标签，并导航到既有仓库路由；不会额外新增仓库标签。
4. 关闭当前标签仍优先激活右侧标签、其次左侧标签；若最后一个标签被关闭，自动创建并激活一个新标签页，而不是留下无标签的首页状态。
5. 无论是否已有项目记录，应用首次进入且没有可恢复标签时，都自动创建一个新标签页。

## 组件边界

- `useOpenTabsStore`：管理标签项、替换当前新标签页、关闭和排序；不加载项目或 Git 数据。
- `RepoTabBar`：按标签类型渲染标题与可用菜单；负责“+”导航至新标签页。
- `DashboardPage`：复用既有最近项目 / 打开仓库界面，接收当前新标签页的 ID；仓库打开成功后请求 Store 替换该标签。
- `OpenRepoDialog` 与最近项目列表：当由新标签页触发时替换当前标签；其余入口保留现有“打开仓库标签”行为。
- Router：为新标签页增加明确路由，不修改仓库页的 Git 加载边界。

## 错误处理与非目标

- 新标签页加载项目列表失败时，复用初始页现有错误提示；不会调用仓库 Git 加载。
- 选择或导入仓库失败时，保留新标签页及其输入状态，让用户可修正后重试。
- 本轮不新增多窗口同步、固定标签、标签分组或独立的“最近项目”数据模型。

## 验收标准

1. 点击“+”新增可关闭、可拖拽的“新标签页”，并显示仓库选择初始页。
2. 新标签页打开仓库后原地变为目标仓库标签，不额外新增标签。
3. 新标签页与仓库标签混排时，切换、关闭与排序符合现有标签规则。
4. 最后一个仓库标签关闭后，界面显示新标签页；无项目记录时亦可打开仓库。
5. 重启后恢复仓库标签与新标签页的顺序；旧持久化仓库 ID 数据可正常恢复。
6. 文案走 i18n；新标签页不直接调用 Git 或 Tauri Command。
7. 通过 `pnpm exec tsc --noEmit`，并按质量文档完成新建、替换、关闭、排序与重启恢复的运行时冒烟。
