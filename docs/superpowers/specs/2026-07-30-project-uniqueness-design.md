# 项目唯一性与重复操作提示设计

日期：2026-07-30

## 目标

添加本地仓库、登记克隆结果等操作必须保证同一物理 Git 仓库只对应一条项目记录。重复操作应向用户说明已有记录，不得静默覆盖项目名称、简介或分组。相同远程仓库允许保留多个本地副本，但克隆前必须提示。

## 唯一性规则

### 本地仓库

- Rust 将输入路径解析为已存在目录，再解析到 Git 顶层目录。
- 使用规范化后的绝对路径判断唯一性。
- 符号链接、仓库子目录、尾斜杠以及平台文件系统上的大小写等价路径视为同一仓库。
- SQLite `projects.path UNIQUE` 继续作为最终一致性防线。
- 再次添加已有仓库不得执行当前的覆盖式 upsert。

### 远程仓库

- 远程仓库不设置数据库唯一约束。
- 比较时移除协议、用户名、默认端口、尾部斜杠和 `.git` 后缀，并按 `host/owner/repository` 生成规范化身份。
- HTTPS 与 SSH 指向同一 `host/owner/repository` 时视为同一远程仓库。
- 命中已有远程仓库只显示警告，用户可以继续克隆到不同目录。

## Rust 与数据层

- 增加项目唯一性检查 Command，接收本地路径或远程 URL，返回：
  - `new`：未发现重复；
  - `existingPath`：本地仓库已登记，并返回已有项目；
  - `existingRemote`：远程仓库已有本地副本，并返回相关项目及路径。
- 本地路径检查必须复用现有路径规范化和 Git 顶层目录解析，不在前端复制路径规则。
- 远程重复检查从已登记项目读取 origin URL，在 Rust 侧完成规范化比较。
- `project_add` 在路径冲突时返回已有项目语义，不修改已有项目字段。
- 添加过程使用数据库事务；多窗口并发添加时仍只保留一条记录。

## 前端交互

### 添加本地仓库

所有添加入口在提交后根据 Rust 结果统一处理：

- 新项目：按现有流程登记或登记并打开。
- 已有项目：显示确认弹窗，说明项目已经存在并展示仓库名称与路径。
- 主操作为“打开已有项目”；管理子窗中的登记模式则提供“查看已有项目”。
- 取消操作不产生数据变更。

### 克隆仓库

- 用户提交克隆表单后、执行网络操作前检查远程身份。
- 命中已有副本时显示警告弹窗，列出已有项目和本地路径。
- 主操作为“继续克隆”，次操作为“取消”。
- 用户继续后仍执行现有目标目录存在性和 Git URL 安全校验。

### 公共行为

- 重复检测和弹窗状态抽取为项目域公共逻辑，避免各入口各自实现。
- 新文案放入 `openRepo`、`cloneRepo` 或项目公共 i18n 资源，同时提供 `zh-CN` 与 `en`。
- 添加、克隆登记成功或重复项目打开后，通过现有 Tauri 事件通知其他窗口刷新项目列表。

## 错误与安全

- 不使用用户输入拼接 shell；Git remote 查询继续通过参数数组执行。
- 无效路径、非 Git 仓库、无效远程 URL继续使用现有领域错误。
- 读取 origin 失败时不阻断克隆，只跳过远程重复提示。
- 弹窗只展示项目名和已登记路径，不展示凭据或含凭据的远程 URL。

## 验收

- 同一路径、仓库子目录、符号链接路径重复添加时只保留一条记录。
- 重复添加不会改变已有项目的名称、简介、图标和分组。
- 重复添加会显示已有项目提示，并能直接打开已有项目。
- HTTPS 与 SSH 指向同一远程仓库时会在克隆前提示，但允许继续。
- 不同远程仓库或同远程仓库不同本地目录均可正常登记。
- 两个窗口同时添加同一仓库不会产生重复记录。
- 主窗与项目管理子窗在操作后保持项目列表一致。
- `pnpm check`、`pnpm build`、`cargo fmt --check` 与 `cargo check` 通过，并完成添加/克隆相关运行时冒烟。
