# 标签模块设计

## 目标

为仓库工作区增加“标签”侧栏模块。用户可浏览与筛选仓库标签，选择标签后在现有历史主区查看该标签指向的提交历史；还可创建附注或轻量标签，并选择将新标签推送至远端。

本轮不提供标签重命名、批量操作或远程标签浏览的独立配置；Git 远端可见的标签由 `fetch` 后的本地 refs 自然反映。

## 用户界面

活动栏在“分支”与 Agent 之间新增 `Tag` 图标。图标按钮遵循现有活动栏样式，包含 `aria-label` 与 Tooltip。

标签侧栏复用分支模块的视觉语言：

1. 顶部显示“标签”、创建按钮和刷新按钮。
2. 过滤输入实时按标签名称过滤。
3. 列表行显示标签图标与完整标签名称；当前选中项使用项目现有的主色浅色背景。
4. 空仓库、无匹配项、加载和读取失败均显示明确状态。

选择标签后，主区切换到历史视图，并将历史范围限定为该标签 ref。用户仍可选择提交、查看详情和文件差异；切换回普通历史时恢复当前分支范围。标签选择不会检出分支、改变 HEAD 或修改工作区。

“创建标签”弹窗包含：

- 基准提交选择器，默认当前 `HEAD`，可从已加载历史中选择提交；
- 必填的标签名称；
- 可选的标签信息。填写信息时创建附注标签，留空时创建轻量标签；
- “推送标签到远端”复选框，默认选中。推送目标固定为优先 `origin`、否则第一个远端；无远端时禁用并说明原因；
- 取消与创建按钮，以及字段级校验和服务错误提示。

标签行右键菜单提供删除操作；删除需二次确认。本轮删除只删除本地标签，不隐式删除远端标签。

## 数据契约与安全

新增类型：

```ts
interface GitTag {
  name: string;
  target: string;
  message?: string;
}
```

新增或完善以下 Git Command，并在 `src/services/git` 中提供唯一前端入口：

| Command | 输入 | 输出 |
| --- | --- | --- |
| `git_tags` | `{ path }` | `{ tags: GitTag[] }` |
| `git_tag_create` | `{ path, name, message?, ref?, push?: boolean, remote?: string }` | `{ ok: true }` |
| `git_tag_delete` | `{ path, name }` | `{ ok: true }` |

创建 Command 使用参数数组执行 `git tag`；有 `message` 时传 `-a` 与 `-m`，没有时创建轻量标签。勾选推送时先本地创建，再执行 `git push <remote> refs/tags/<name>`；`<remote>` 优先为 `origin`，否则为第一个已配置远端。推送失败返回领域错误，前端明确提示“标签已在本地创建，但推送失败”，并保留刷新入口。

所有路径参数继续经 Rust 仓库根校验。标签名和 ref 在 Rust 侧使用 Git 的 ref 规则验证；不得将用户输入拼接为 shell 命令。删除仅执行 `git tag -d -- <name>`，不执行远端删除。

历史加载通过现有 `git_log` 的 `ref` 参数传入选中的标签名，不增加新的日志 Command。标签名在 Service 层按普通数据传递，Rust 负责 ref 校验。

## 前端结构与状态

新增：

- `src/components/git/TagList.tsx`：侧栏列表、过滤、刷新、选择、创建与删除入口。
- `src/components/git/CreateTagDialog.tsx`：创建标签表单与提交状态。
- `src/services/git/git.tag.ts`：标签 Command 的 Service 封装。

调整：

- `ActivityBar` 增加 `tags` 视图与标签入口。
- `RepoPage` 在侧栏渲染 `TagList`；标签选中时调用 store 的日志刷新并切至历史视图。
- `useRepoStore` 保存当前日志 ref，防止分页加载或刷新时丢失标签筛选。
- `src/types/git.ts`、`src/services/git/index.ts`、双语 i18n、Command/API 文档补齐标签契约。

标签列表自身状态保持在 `TagList`，仓库级标签数据与加载状态进入 `useRepoStore`，随现有 `loadAll`、`fetch` 与创建/删除操作刷新。避免 Zustand selector 中创建新的空数组或对象。

## 错误处理与一致性

- 无标签、无匹配标签和无可选基准提交均使用空状态，不显示空白面板。
- 标签名称为空、格式非法或已存在时阻止提交并给出可见错误。
- `git_tags`、创建、删除、推送失败均经 Service 规范化后展示 toast 或表单内错误，不吞掉异常。
- 创建、删除、推送完成后刷新标签和当前日志；写操作进行中禁用重复提交。
- 切换仓库时，标签选择和创建弹窗状态不泄漏到新仓库。

## 验收标准

1. 活动栏可通过鼠标与键盘切换到“标签”，悬停有 Tooltip。
2. 侧栏展示真实 Git 标签，可按名称过滤、刷新和选择。
3. 选择标签后，主区显示该标签范围的提交历史，提交详情与文件对比仍可用。
4. 能以当前 HEAD 或指定已加载提交创建轻量或附注标签；创建后立即出现在列表中。
5. 选择推送时，标签被推送到选定远端；推送失败时明确提示本地创建结果。
6. 删除标签需确认且只删除本地标签。
7. 类型检查、相关 Rust 测试和桌面端冒烟通过；无已知 S0/S1。
