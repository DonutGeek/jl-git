# 新标签页 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将“+”改为创建可持久化的新标签页，并让该标签复用仓库选择初始页、原地替换为打开的仓库。

**Architecture:** 用判别联合类型替换仅保存仓库 ID 的标签列表：仓库标签携带 `projectId`，新标签页携带独立 `id`。路由以 `/tab/:tabId` 表示新标签页，标签栏只负责导航与标签交互，`DashboardPage` 只负责项目列表和把当前新标签页替换成仓库标签。

**Tech Stack:** React 19、TypeScript strict、React Router、Zustand persist、i18next、dnd-kit、Tailwind CSS 4。

## Global Constraints

- 不引入新依赖或第二套状态方案；全局标签状态只保留在 `src/store/useOpenTabsStore.ts`。
- 用户可见文案必须同时写入 `zh-CN` 与 `en` i18n 资源；不得硬编码颜色。
- UI 不直接调用 `invoke`、不访问 Git；仓库加载继续只在既有 `RepoPage` 完成。
- 保持现有工作区的无关修改不被暂存、覆盖或格式化。

### Task 1: 将标签 Store 改为可区分的持久化标签项

**Files:**
- Modify: `src/store/useOpenTabsStore.ts`

**Interfaces:**
- Consumes: Zustand `persist` 中已有的 `jlgit-open-tabs` 数据；旧数据形状为 `{ tabIds: string[] }`。
- Produces:

```ts
export type OpenTab =
  | { id: string; type: "new-tab" }
  | { id: string; type: "repository"; projectId: string };

interface OpenTabsState {
  tabs: OpenTab[];
  openNewTab: () => string;
  openRepositoryTab: (projectId: string) => void;
  replaceNewTabWithRepository: (tabId: string, projectId: string) => boolean;
  closeTab: (tabId: string) => string | null;
  // closeOtherTabs / closeTabsToLeft / closeTabsToRight / reorderTabs / pruneTabs
  // 均接收 tabId；pruneTabs 仅移除失效的 repository 标签。
}
```

- [ ] **Step 1: 写出状态转换表并在注释中固定不变量**

在 Store 顶部记录以下转换，确保实现、迁移和调用方使用同一套 ID 语义：

| 操作 | 输入 | 输出 |
| --- | --- | --- |
| `openNewTab()` | 无 | 追加 `{ id: crypto.randomUUID(), type: "new-tab" }` 并返回 id |
| `openRepositoryTab(projectId)` | 项目 ID | 若已有该项目的仓库标签则不写入，否则追加 `{ id: projectId, type: "repository", projectId }` |
| `replaceNewTabWithRepository(tabId, projectId)` | 当前新标签页 ID、项目 ID | 原位置替换；若项目已有仓库标签则移除当前新标签页并返回 `false` |
| `closeTab(tabId)` | 标签 ID | 删除目标，返回右侧邻居 ID；没有邻居时返回 `null` |

- [ ] **Step 2: 实现判别联合、所有 tabId 操作及无变化保护**

将 `tabIds` 全部替换为 `tabs`。关闭、保留左右、重排均先通过 `tab.id` 定位；`pruneTabs(validIds)` 仅过滤 `type === "repository" && !validIds.has(tab.projectId)` 的标签。每个找不到 ID、无需排序或状态未变的分支返回原状态/提前返回，避免无意义 Zustand 通知。

核心替换逻辑应保持原位置并避免同仓库重复：

```ts
replaceNewTabWithRepository(tabId, projectId) {
  const { tabs } = get();
  const index = tabs.findIndex((tab) => tab.id === tabId && tab.type === "new-tab");
  if (index < 0) return false;

  const existing = tabs.find((tab) => tab.type === "repository" && tab.projectId === projectId);
  if (existing) {
    set({ tabs: tabs.filter((tab) => tab.id !== tabId) });
    return false;
  }

  const next = [...tabs];
  next[index] = { id: projectId, type: "repository", projectId };
  set({ tabs: next });
  return true;
}
```

- [ ] **Step 3: 为已持久化的 `tabIds` 增加版本化迁移**

将 persist 配置的版本更新为 `1`，使用 `migrate` 将旧数组转换为仓库标签：

```ts
const legacyTabIds = Array.isArray(state.tabIds) ? state.tabIds : [];
return {
  ...state,
  tabs: legacyTabIds.map((projectId) => ({
    id: projectId,
    type: "repository" as const,
    projectId,
  })),
};
```

迁移边界以 `unknown` 接收并用对象、数组和字符串守卫收窄，禁止 `any`。`partialize` 只写 `{ tabs }`。

}
